# Compatibility and validation

The entire repository is archived: 579 tracked files, including its 94 canonical `.claude/skills` guides, shared references, `.cursor` mirror, client configurations, docs and website sources. The mirror does not count as another 94 unique skills. Only the top-level Codex adapter is registered globally; all specialist documents are available by path through the module index.

Every original Git blob was checked against the pinned repository tree. Module paths, bundled source integrity, Codex metadata and checked extraction were validated locally. The collection consists of instructions and art-direction references, not a packaged model generator. Individual styles, every possible production chain, simulations and engine integrations have not been executed as separate tests.

Use native Blender 5.2.1 background Python for local saved-file work, or actual discovered MCP tools when a live bridge is available. The source `.mcp.json` and `.cursor/mcp.json` are archived examples, not installed Codex configuration. Preserve working services; configure a live backend only for that concrete runtime branch.

Read the source director for routing concepts and only the needed specialist guides. Its production-planning and style assumptions should be scaled to the user's asset. AAA budgets, fog, strict naming, engine export, simulation and multiple agents are not mandatory for every task. Style guidance describes a visual target, not a validation theorem. Verify current units/axes and actual import behavior in the requested engine; review both appearance and editable geometry.
