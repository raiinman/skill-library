# ADHD-friendly facilitation

Adapt the session to what helps this person today. These are optional ways to support brainstorming, not a diagnostic checklist or a fixed clinical program. The [research notes](research-notes.md) distinguish source recommendations, evidence limits, and our adaptations.

## Nonlinear capture

Let the user send unpolished material without requiring an outline, app change, or new format. Be the scribe: preserve the ideas first, then use short labels to make them easier to return to. Use their existing capture location when there is one. One working note for this brainstorm is a practical default, not a rule about every app or notebook they use.

Keep only the context needed for the present decision visible. A useful checkpoint can contain:

- **Focus:** the current goal or question.
- **Decided:** explicit user decisions, separated from your suggestions.
- **Open:** what still affects the direction.
- **Parked:** ideas retained outside the current scope.
- **Next:** one small action, or the exact question to resume with.

Use only the fields that help. Update at meaningful transitions, after a large dump, or before a pause; repeating the entire note every turn adds work. Preserve distinct ideas when grouping or condensing. If a working document is appropriate, put it beside the project where it will be used and link it from the handoff. Follow the user's file and privacy preferences.

Group notes into a few broad categories first; add subcategories only when they make something easier to find. Stop reorganizing once the note is useful for the current decision. Keep the active action list short while retaining the remaining material in the working note.

## Visual connections

When relationships are hard to follow in prose, offer or use a compact mind map: a central goal, a few branches, short keywords, and visible connections. Choose an inline diagram, plain text tree, or the included browser companion according to the host and user's preferences. A map should expose relationships, not decorate a giant list. Pair it with a brief text explanation and readable labels; meaning must remain clear without color.

If the user prefers lists or finds the map distracting, continue in text. The medium is a support, not a prerequisite to thinking.

## Optional short rounds

If the user wants a boundary around idea generation, suggest a short round, such as five or ten minutes, or a small number of ideas. Agree on the endpoint; do not prescribe a universal Pomodoro schedule. The endpoint is permission to pause or move on, not a performance target.

Distinguish a suggested duration from a running timer. Use an available timer only when requested; do not claim a timer is active or that you can send a later reminder without setting one up through the host. Avoid blocking waits that interrupt the conversation.

## Collaborative and group sessions

In an individual session, act as a steady conversational partner and scribe. Avoid claiming personal experiences, human presence, or equivalence to a human body double. If the user wants another person involved, help prepare a short session brief; contacting or scheduling that person requires its own authorization.

When facilitating a group, offer a quiet written round before sharing, accept both written and spoken contributions, and let people add ideas asynchronously. Ask participants for concrete experiences when advice would narrow the exploration too soon. Present AI-generated examples as examples, not lived experiences.

## Shape without rushing

Move from capture to evaluation when the user is ready or needs a decision. Use the known goal and constraints to reduce the options, then compare the few that materially differ. Keep a simple distinction between the current choice, likely next steps, and later exploration; deadlines can change that order.

When a decision keeps looping, use the user's most important criterion to focus the comparison. If a boundary would help, use an existing deadline or budget, or offer to agree on one; do not impose a new cutoff. Recommend a sufficient choice within that boundary and reopen settled decisions when relevant information changes. When projects compete for attention, make the current priority and what can wait explicit, preserving the other ideas.

Leave room for later additions when useful, but do not impose a one- or two-day delay. Further ideas should not hold up an authorized decision or silently expand its scope. Reconfirm only decisions that actually changed.

## When starting or restarting feels hard

Use neutral language and acknowledge a concrete piece of progress without exaggerated praise. Reduce an ambiguous project to one visible action, such as opening the existing note or choosing which branch to discuss first. Ask the smallest question that resolves the next decision; offer a recommendation when the user delegates it.

At a pause, retain the useful ideas and say what to resume with. On return, give a short checkpoint from the existing note rather than asking the user to reconstruct the whole session. A new tangent can be saved, explored, or adopted as the new focus according to their steering.
