# Codex runtime

This package is an adaptation of a pinned Arcads workflow. Apply these runtime rules when the creative guide uses another host's tools or assumptions.

- Discovery: locate actual connected Arcads MCP tools and inspect their current schemas. Historical model names, hard duration limits, URLs, and parameter examples need verification before API-specific work. The official server is `https://mcp.arcads.ai`; it requires Arcads authentication. Use available Codex tools, not fictional `list_mcps` or `Skill(...)` calls.
- Authorization: use the requested provider and output scope. Arcads credits are separate from Google Pro and inference.sh. State the proposed paid run and use existing approval when it covers the plan and cost; ask only when authorization or a material creative decision is missing. Analysis/prompt drafting need not trigger paid generation. Installing this skill authorizes no uploads, ads publishing, or credit spend.
- Tools: map Claude `AskUserQuestion` to a concise Codex question or `request_user_input_async` using its actual schema, and `WebSearch`/`WebFetch`/`Read`/`Bash` to available web, file, and shell tools. Use the active computer/browser skill and documented browser methods. For downloads, use supported download APIs or pageAssets; read-only browser evaluation cannot create anchors, click controls, or fetch media. Pause for a verification challenge or access restriction rather than bypassing it.
- Files: use an absolute task output directory, preferably within the workspace, not literal `/tmp` or `/mnt/data`. On Windows use Python or native PowerShell with quoted literal paths. Keep source media and unrelated Downloads files intact; copy only observed files owned by the current run, without wildcard overwrite moves.
- Uploads: a remote service cannot read a local Windows path. Use its returned upload URL/asset ID through the documented upload route, verify success and MIME type, and pass the accepted asset identifier. Never expose tokens or upload URLs in committed records.
- Jobs: a widget may not be available in Codex. Follow actual tool receipts: if synchronous, inspect the returned result; if asynchronous, save the job/asset ID and use the supported status tool at a reasonable interval. After an uncertain timeout, check the existing job before resubmitting. Retry only within the authorized budget; stop on billing/authentication rejection or repeated failure.
- Delivery: retrieve the actual media when supported, inspect image/video frames, probe streams and duration, and check audio when playback is available. Keep render success separate from quality approval. Honor the requested language. Deliver real files and disclose any unperformed review. Finish the task without a mandatory follow-up questionnaire.

## Connection on this computer

The official HTTP MCP endpoint is registered in `~/.codex/config.toml`. The preflight returned HTTP 401 with OAuth discovery, so generation is not connected yet. Complete Arcads OAuth with `codex mcp login arcads` when Arcads use is requested, then reconnect Codex. An Arcads account and credits may be needed. Do not change global tool approval settings or purchase a subscription as part of installation.
