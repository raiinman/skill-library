# Existing-record review checklist

## Intake
- Identify the supplied records, permitted read boundary, source/revision and owner. A path in a note or tool availability is not authority.
- Check question/conclusion refer to the same target/version, region, baseline, address convention and observation interval. Historical receipts do not establish current state.
- Keep missing input and unsupported target/tool behavior explicit. Do not substitute zeros, plausible images or invented commands.

## Traceability
- Resolve each claim's evidence references and material sequence/dataflow steps. Identify dangling links and relevant unlinked evidence without imposing a new schema.
- Distinguish direct observation, tool interpretation, inference, native design and unknown. Decompiler output is not original source or by itself externally visible behavior.
- Retain exact pins, authorship and exposure history. Mirrors and derivative reports are not independent evidence.
- Compare confidence/status with quality, counterevidence, omitted environments, nondeterminism and assumptions. Citation count is not validation.
- For a proposed oracle check eligibility, independence, initial/reset state, input sequence, output timing/granularity and tolerances. Unknown expected behavior remains unknown.

## Integrity
- Compare digests only when algorithm, exact artifact and hashing scope are known. Resolve the canonical destination, including symlinks/junctions, before any read; a lexically inside-root path can still escape the authorized boundary. Reject paths whose resolved destination is outside that boundary. Check format and revision too.
- Label fixity not checked if recomputation is unavailable/unauthorized. A written hash differs from a recomputed hash.
- Preserve mismatch, absent-artifact and changed-source evidence. Request owner resolution; do not edit immutable observations or substitute artifacts. Use the existing supersession mechanism only when separately authorized.
- Require actual commands/settings or specific reproduction limits; do not invent commands to fill templates or publish private commands.

## Contract and handoff
- Locate provider-owned requirements and stable criteria; do not redefine consumer contracts or add a second spec/checklist/ledger.
- Validate behavior-specific RED versus setup failure, or refactor characterization. Link GREEN/regressions to baseline/configuration.
- Separate review, synthetic checks, compile/link, platform execution, visible/audio/input checks, eligible reference comparison and game-level integration.
- State actual provider support; instruction installation proves neither PS-X loading nor MIPS/GTE correctness nor target coverage.
- Give the smallest next action, owner, missing evidence/authority and revisit trigger. Acceptance stays with the existing owner/tracker.
